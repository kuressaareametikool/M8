## Step 1 — Flyway migrations

```sql
-- src/main/resources/db/migration/V8__add_invoice_id_to_time_entries.sql
alter table time_entries
    add column invoice_id bigint references invoices (id) on delete restrict;
```

**What happens:**

1. `generated by default as identity` is the standard SQL way to get an auto-increment id in
   PostgreSQL. Hibernate's `GenerationType.IDENTITY` works with it.
2. `number varchar(9) not null unique` — `2026-0001` is exactly 9 characters. PostgreSQL creates a
   unique index named `invoices_number_key`. It is our last line of defence against duplicates (R11).
3. All money columns are `bigint` cents (R1), like the money columns on `projects`; in Java they are
   `long`. `vat_rate_bp` stores 24 % as `2400` (R2) — a rate, not money, so `integer` is enough.
4. `invoice_lines.invoice_id ... on delete cascade`: deleting an invoice deletes its lines.
5. `time_entries.invoice_id` is nullable (not invoiced yet) and `on delete restrict`: PostgreSQL refuses
   to delete an invoice that still has entries. The code must release them first (Step 8). Forgetting
   gives an error instead of silently losing data.
6. `invoice_lines` has no timestamps — PROJECT.md does not list them.

**Check it works:** start the application (`./mvnw spring-boot:run -Dspring-boot.run.profiles=dev`). The log shows
`Successfully applied 3 migrations to schema "public", now at version v8`. Because
`spring.jpa.hibernate.ddl-auto=validate`, the app will **fail to start** at Step 3 if an entity does not
match these tables — that is a feature, not a bug.

## Step 2 — `InvoiceStatus`

```java
// src/main/java/ee/ta25/billable/invoice/InvoiceStatus.java
package ee.ta25.billable.invoice;

import jakarta.persistence.EnumeratedValue;

/** The life cycle of an invoice: draft → sent → paid (R13). */
public enum InvoiceStatus {
  DRAFT("draft", "Draft"),
  SENT("sent", "Sent"),
  PAID("paid", "Paid");

  @EnumeratedValue private final String dbValue;
  private final String label;

  InvoiceStatus(String dbValue, String label) {
    this.dbValue = dbValue;
    this.label = label;
  }

  public String dbValue() {
    return dbValue;
  }

  public String label() {
    return label;
  }

  /** Only a draft may be edited or deleted. */
  public boolean canEdit() {
    return this == DRAFT;
  }

  /** The allowed moves. Everything not listed here is forbidden. */
  public boolean canTransitionTo(InvoiceStatus to) {
    return switch (this) {
      case DRAFT -> to == SENT;
      case SENT -> to == PAID;
      case PAID -> false;
    };
  }
}
```

**What happens:**

1. The `switch` expression must cover every constant. If you add `CANCELLED` later, the compiler
   refuses to compile until you handle it — the state machine cannot silently get a hole.
2. `canTransitionTo()` is the README's transition table as code. `DRAFT → DRAFT` is `false`: staying
   still is not a transition.
3. `@EnumeratedValue` works exactly as for `BillingType` in lesson 03: together with
   `@Enumerated(EnumType.STRING)` on the entity field (step 3), Hibernate stores `draft`, not `DRAFT`.

**What happens:**

1. Money fields are `long` (columns `bigint`); `vatRateBp` and `minutes` are `int` (columns `integer`).
   The Java type must match the column type exactly, or schema validation stops the application
   (see Troubleshooting). The entity stores plain cents; `subtotal()`, `vat()` and `total()` wrap them
   in `Money` for calculations and display.
2. `@OneToMany(mappedBy = "invoice")` says "the foreign key lives on `InvoiceLine.invoice`".
   `cascade = CascadeType.ALL` means saving the invoice also saves its new lines, and deleting it
   deletes them. `orphanRemoval = true` deletes a line that is removed from the list.
3. `addLine()` sets **both** sides of the relation. JPA only writes what the owning side
   (`InvoiceLine.invoice`) says; if you only did `lines.add(line)`, the line would be saved with
   `invoice_id = NULL` and fail the `not null` constraint.
4. `getLines()` returns a read-only view, so nobody can add a line without `addLine()`.
5. `changeStatus()` is package-private: only classes in `invoice` (the service) can change the status.
6. `ProjectAmount` is filled by a **constructor expression** (`select new ...`). `sum()` of a `long`
   field is a `Long` in JPQL.
7. `findMaxNumberLike` returns `Optional.empty()` when there are no invoices (SQL `MAX` returns `NULL`).
8. `findInvoiceable` uses `join fetch e.project` — one query returns the entries **and** their
   projects, so reading `entry.getProject()` later does not trigger N+1 (lesson 06). The condition
   `e.endedAt < :before` with `before` = midnight **after** the chosen day means "ended on or before that
   day". `p.billingType <> :excluded` leaves out internal projects (lesson 08's Null Object type): they
   are never billed, so their entries stay out of invoices and stay editable. The enum is passed as a
   parameter, so Hibernate binds it as `'internal'` (the `@EnumeratedValue` mapping from lesson 03).
9. `releaseFrom` is a bulk `UPDATE`. `@Modifying` tells Spring Data it is not a `SELECT`.
10. `@EntityGraph` loads the listed relations in the same query, because `open-in-view` is `false` and
    the view cannot load them later.
11. `findAllByOrderByIssuedOnDescIdDesc()` returns **all** invoices as a `List`. The Laravel track
    paginates this page from the start (`paginate(20)`); here we keep the list simple and paginate it in
    lesson 14 (independent task 3) with `Page<Invoice> findAll(Pageable)`, the same way as the clients
    list in lesson 04.

## Step 4 — `TimeSlot`, `Overlap` and `OverlapDetector`

The algorithm needs no JPA: only start, end and something to name the entry in the error. Giving it
plain records keeps it pure and trivially testable.

```java
// src/main/java/ee/ta25/billable/invoice/TimeSlot.java
package ee.ta25.billable.invoice;

import java.time.LocalDateTime;
import java.util.Objects;

/** The part of a time entry that the overlap check needs. */
public record TimeSlot(long entryId, LocalDateTime start, LocalDateTime end, String description) {

  public TimeSlot {
    Objects.requireNonNull(start, "start");
    Objects.requireNonNull(end, "end");
    if (!end.isAfter(start)) {
      throw new IllegalArgumentException("Time slot " + entryId + " must end after it starts");
    }
  }

  /** Touching slots (one ends exactly when the other starts) do not overlap. */
  public boolean overlaps(TimeSlot other) {
    return start.isBefore(other.end) && other.start.isBefore(end);
  }
}
```

```java
// src/main/java/ee/ta25/billable/invoice/OverlapDetector.java
package ee.ta25.billable.invoice;

import java.util.Comparator;
import java.util.List;
import java.util.Optional;
import org.springframework.stereotype.Component;

/**
 * Finds two time slots that overlap (R10).
 *
 * <p>Sorts by start (then end) and sweeps once, remembering the slot with the latest end seen so
 * far. Time O(n log n) because of the sort; extra space O(n) for the sorted copy.
 */
@Component
public class OverlapDetector {

  private static final Comparator<TimeSlot> BY_START_THEN_END =
      Comparator.comparing(TimeSlot::start).thenComparing(TimeSlot::end);

  public Optional<Overlap> find(List<TimeSlot> slots) {
    List<TimeSlot> sorted = slots.stream().sorted(BY_START_THEN_END).toList();

    TimeSlot latest = null;
    for (TimeSlot slot : sorted) {
      if (latest != null && slot.start().isBefore(latest.end())) {
        return Optional.of(new Overlap(latest, slot));
      }
      if (latest == null || slot.end().isAfter(latest.end())) {
        latest = slot;
      }
    }
    return Optional.empty();
  }
}
```

**What happens:**

1. A **compact constructor** (`public TimeSlot { ... }`) runs before the fields are assigned. It
   rejects a slot that does not end after it starts. The record is immutable.
2. `stream().sorted(...).toList()` sorts a **copy**; the caller's list is not touched (and `List.of()`
   lists could not be sorted in place anyway).
3. `Comparator.comparing(TimeSlot::start).thenComparing(TimeSlot::end)` sorts by start, and by end when
   two starts are equal.
4. The loop is the sweep from the README. `isBefore` is strict, so touching slots are fine.
5. `@Component` lets Spring inject it, but it has no dependencies, so tests simply use
   `new OverlapDetector()`.

## Step 6 — `InvoiceNumberGenerator`

```java
// src/main/java/ee/ta25/billable/invoice/InvoiceNumberGenerator.java
package ee.ta25.billable.invoice;

import java.util.regex.Matcher;
import java.util.regex.Pattern;
import org.springframework.stereotype.Component;

/**
 * Gives out invoice numbers in the form YYYY-NNNN, sequential per year (R11).
 *
 * <p>Must run inside the transaction that saves the invoice. Lesson 14 replaces "max + 1" with a
 * locked sequence row, because two parallel requests can read the same maximum.
 */
@Component
public class InvoiceNumberGenerator {

  private static final Pattern NUMBER = Pattern.compile("^\\d{4}-(\\d{4})$");

  private final InvoiceRepository invoices;

  public InvoiceNumberGenerator(InvoiceRepository invoices) {
    this.invoices = invoices;
  }

  public String next(int year) {
    int last =
        invoices.findMaxNumberLike(year + "-%").map(InvoiceNumberGenerator::sequenceOf).orElse(0);
    return format(year, last + 1);
  }

  static String format(int year, int sequence) {
    if (sequence < 1 || sequence > 9999) {
      throw new IllegalArgumentException(
          "Invoice sequence must be between 1 and 9999, got " + sequence);
    }
    return "%04d-%04d".formatted(year, sequence);
  }

  static int sequenceOf(String number) {
    Matcher matcher = NUMBER.matcher(number);
    if (!matcher.matches()) {
      throw new IllegalArgumentException("\"" + number + "\" is not an invoice number");
    }
    return Integer.parseInt(matcher.group(1));
  }
}
```

**What happens:**

1. `findMaxNumberLike("2026-%")` runs `SELECT MAX(number) FROM invoices WHERE number LIKE '2026-%'`.
   Zero-padding makes the text maximum equal to the numeric maximum.
2. No invoices yet → `Optional.empty()` → `orElse(0)` → sequence 1 → `2026-0001`.
3. `sequenceOf()` validates with a regular expression and extracts the digits after the dash.
4. `format()` refuses 0 and 10,000 (`2026-10000` would not fit into `varchar(9)`).
5. `format()` and `sequenceOf()` are package-private and `static`, so the test in the same package can
   call them directly without a repository.

## Step 7 — `InvoiceGenerator`, the orchestrator

```java
// src/main/java/ee/ta25/billable/invoice/InvoiceGenerator.java
package ee.ta25.billable.invoice;

import ee.ta25.billable.billing.BillingStrategyResolver;
import ee.ta25.billable.client.Client;
import ee.ta25.billable.common.BillableProperties;
import ee.ta25.billable.common.DueDateCalculator;
import ee.ta25.billable.common.Money;
import ee.ta25.billable.common.TimeRounding;
import ee.ta25.billable.project.BillingType;
import ee.ta25.billable.project.Project;
import ee.ta25.billable.timeentry.TimeEntry;
import ee.ta25.billable.timeentry.TimeEntryRepository;
import java.time.Clock;
import java.time.LocalDate;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

/**
 * Turns a client's billable, un-invoiced time entries into one draft invoice.
 *
 * <p>Everything happens in one transaction: if any rule fails, nothing is saved.
 */
@Service
public class InvoiceGenerator {

  private final TimeEntryRepository timeEntries;
  private final InvoiceRepository invoices;
  private final InvoiceLineRepository invoiceLines;
  private final OverlapDetector overlapDetector;
  private final BillingStrategyResolver strategies;
  private final InvoiceNumberGenerator numbers;
  private final DueDateCalculator dueDates;
  private final Clock clock;
  private final int vatRateBp;

  public InvoiceGenerator(
      TimeEntryRepository timeEntries,
      InvoiceRepository invoices,
      InvoiceLineRepository invoiceLines,
      OverlapDetector overlapDetector,
      BillingStrategyResolver strategies,
      InvoiceNumberGenerator numbers,
      DueDateCalculator dueDates,
      Clock clock,
      BillableProperties settings) {
    this.timeEntries = timeEntries;
    this.invoices = invoices;
    this.invoiceLines = invoiceLines;
    this.overlapDetector = overlapDetector;
    this.strategies = strategies;
    this.numbers = numbers;
    this.dueDates = dueDates;
    this.clock = clock;
    this.vatRateBp = settings.vatRateBp();
  }

  /**
   * Generates a draft invoice for all entries that ended on or before {@code upTo}.
   *
   * @throws NothingToInvoiceException if there is nothing to invoice
   * @throws OverlappingEntriesException if two of the entries overlap (R10)
   */
  @Transactional
  public Invoice generate(Client client, LocalDate upTo) {
    List<TimeEntry> entries =
        timeEntries.findInvoiceable(client, upTo.plusDays(1).atStartOfDay(), BillingType.INTERNAL);
    if (entries.isEmpty()) {
      throw new NothingToInvoiceException(client, upTo);
    }

    assertNoOverlaps(entries);

    LocalDate issuedOn = LocalDate.now(clock);
    Invoice invoice =
        new Invoice(
            client,
            numbers.next(issuedOn.getYear()),
            issuedOn,
            dueDates.dueDate(issuedOn),
            vatRateBp);
    buildLines(entries).forEach(invoice::addLine);

    Money subtotal =
        Money.sum(invoice.getLines().stream().map(InvoiceLine::amount).toArray(Money[]::new));
    invoice.applyTotals(subtotal, subtotal.percentageBp(vatRateBp));

    Invoice saved = invoices.save(invoice);
    entries.forEach(entry -> entry.assignTo(saved));
    return saved;
  }

  private void assertNoOverlaps(List<TimeEntry> entries) {
    List<TimeSlot> slots =
        entries.stream()
            .map(
                entry ->
                    new TimeSlot(
                        entry.getId(),
                        entry.getStartedAt(),
                        entry.getEndedAt(),
                        entry.getDescription()))
            .toList();

    overlapDetector
        .find(slots)
        .ifPresent(
            overlap -> {
              throw new OverlappingEntriesException(overlap);
            });
  }

  /** One line per project: rounded minutes and the amount from the project's strategy. */
  private List<InvoiceLine> buildLines(List<TimeEntry> entries) {
    Map<Long, List<TimeEntry>> byProject =
        entries.stream()
            .collect(
                Collectors.groupingBy(
                    entry -> entry.getProject().getId(), LinkedHashMap::new, Collectors.toList()));

    Map<Long, Long> alreadyBilled =
        invoiceLines.sumAmountByProject(byProject.keySet()).stream()
            .collect(Collectors.toMap(ProjectAmount::projectId, ProjectAmount::amountCents));

    List<InvoiceLine> lines = new ArrayList<>();
    for (List<TimeEntry> projectEntries : byProject.values()) {
      Project project = projectEntries.getFirst().getProject();
      int minutes = projectEntries.stream().mapToInt(entry -> roundedMinutes(entry, project)).sum();
      Money billed = Money.fromCents(alreadyBilled.getOrDefault(project.getId(), 0L));
      Money amount = strategies.forProject(project).calculate(project, minutes, billed);

      if (minutes == 0 && amount.isZero()) {
        continue;
      }
      lines.add(new InvoiceLine(project, describe(project, minutes), minutes, amount));
    }
    return lines;
  }

  private static int roundedMinutes(TimeEntry entry, Project project) {
    // durationMinutes() is the lesson 10 version (correct across DST), as in ProjectService.
    return Math.toIntExact(
        TimeRounding.roundUp(entry.durationMinutes(), project.getRoundingMinutes()));
  }

  static String describe(Project project, int minutes) {
    return "%s — %d h %02d min".formatted(project.getName(), minutes / 60, minutes % 60);
  }
}
```

**What happens** when `generate(client, 2026-09-30)` is called:

1. `@Transactional` makes Spring wrap the call in a proxy: it opens a transaction before the method and
   commits after it returns. If a `RuntimeException` leaves the method, it rolls back instead. This only
   works when the call comes **from another bean** (the proxy is skipped for `this.generate(...)`) and
   the method is not `private` (since Spring 6.0, `protected` and package-private methods work too on
   class-based proxies; we keep it `public` because the service calls it).
2. `findInvoiceable()` runs **one** query with `join fetch`: this client's entries (internal projects
   excluded) that are not invoiced, billable, and ended before midnight after `upTo`.
3. No entries → `NothingToInvoiceException`.
4. `assertNoOverlaps()` maps entries to `TimeSlot`s and asks the detector. `ifPresent(... throw ...)`
   throws from inside a lambda — allowed because the exception is unchecked.
5. `LocalDate.now(clock)` — "today" comes from the injected `Clock`, so tests can fix it (lesson 12).
   `DueDateCalculator.dueDate()` applies R12. `numbers.next(2026)` runs inside the transaction: a later failure
   rolls the invoice back and the number was never used.
6. `buildLines()`:
   - `groupingBy(..., LinkedHashMap::new, ...)` groups entries by project id and keeps the order of
     first appearance (entries are sorted by start time), so lines come out in a stable order;
   - one aggregate query loads what each project has already been billed (R7, R8);
   - each entry is rounded **separately** (R5), then the minutes are summed. `Math.toIntExact()`
     turns `roundUp()`'s `long` into the `int` stored in `invoice_lines.minutes`, and **throws** if it
     does not fit instead of silently wrapping to a negative number;
   - the resolver picks the strategy (lesson 08) and the strategy prices the minutes;
   - a line with 0 minutes **and** 0 € is skipped; minutes with 0 € (fixed price already fully billed)
     is kept so the client sees the work.
7. The subtotal is the sum of the line amounts, with `Money.sum()` from lesson 11 — the call that method
   was built for. VAT is
   calculated **once** on the subtotal (R3), with the rate from `billable.vat-rate-bp` in
   `application.properties`, read through `BillableProperties.vatRateBp()` (lessons 09–10). The rate
   is copied onto the invoice (R2), so changing the property later does not change old invoices.
8. `invoices.save(invoice)` persists the invoice; `cascade = ALL` persists every line with it.
9. `entry.assignTo(saved)` changes managed entities. We do not call `save()` for them: at commit,
   Hibernate's **dirty checking** notices the changed field and issues the `UPDATE time_entries SET
   invoice_id = ...` itself.

```java
// src/main/java/ee/ta25/billable/invoice/InvoiceService.java
package ee.ta25.billable.invoice;

import ee.ta25.billable.client.Client;
import ee.ta25.billable.client.ClientRepository;
import ee.ta25.billable.common.NotFoundException;
import ee.ta25.billable.timeentry.TimeEntryRepository;
import java.time.LocalDate;
import java.util.List;
import org.springframework.data.domain.Sort;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class InvoiceService {

  private final InvoiceRepository invoices;
  private final ClientRepository clients;
  private final TimeEntryRepository timeEntries;
  private final InvoiceGenerator generator;

  public InvoiceService(
      InvoiceRepository invoices,
      ClientRepository clients,
      TimeEntryRepository timeEntries,
      InvoiceGenerator generator) {
    this.invoices = invoices;
    this.clients = clients;
    this.timeEntries = timeEntries;
    this.generator = generator;
  }

  @Transactional(readOnly = true)
  public List<Invoice> findAll() {
    return invoices.findAllByOrderByIssuedOnDescIdDesc();
  }

  @Transactional(readOnly = true)
  public Invoice getWithLines(Long id) {
    return invoices.findWithLinesById(id).orElseThrow(() -> notFound(id));
  }

  @Transactional(readOnly = true)
  public List<Client> clientsForSelect() {
    return clients.findAll(Sort.by("name"));
  }

  @Transactional
  public Invoice generate(Long clientId, LocalDate upTo) {
    Client client =
        clients
            .findById(clientId)
            .orElseThrow(() -> new NotFoundException("Client " + clientId + " not found"));
    return generator.generate(client, upTo);
  }

  @Transactional
  public Invoice send(Long id) {
    return moveTo(id, InvoiceStatus.SENT);
  }

  @Transactional
  public Invoice markPaid(Long id) {
    return moveTo(id, InvoiceStatus.PAID);
  }

  /** Deletes a draft and releases its time entries so they can be invoiced again (R13). */
  @Transactional
  public String delete(Long id) {
    Invoice invoice = invoices.findById(id).orElseThrow(() -> notFound(id));
    if (!invoice.getStatus().canEdit()) {
      throw new InvoiceNotEditableException(invoice);
    }
    timeEntries.releaseFrom(invoice);
    invoices.delete(invoice);
    return invoice.getNumber();
  }

  private Invoice moveTo(Long id, InvoiceStatus to) {
    Invoice invoice = invoices.findById(id).orElseThrow(() -> notFound(id));
    if (!invoice.getStatus().canTransitionTo(to)) {
      throw new InvalidStatusTransitionException(invoice.getStatus(), to);
    }
    invoice.changeStatus(to);
    return invoice;
  }

  private static NotFoundException notFound(Long id) {
    return new NotFoundException("Invoice " + id + " not found");
  }
}
```

**What happens:**

1. `generate()` is `@Transactional`, and so is `InvoiceGenerator.generate()`. The default propagation
   `REQUIRED` means "join the existing transaction": loading the client and generating the invoice
   happen in **one** transaction.
2. `moveTo()` asks the enum first; a forbidden move throws and nothing changes. An allowed move only
   changes the field — dirty checking writes it at commit.
3. `delete()` refuses anything that is not a draft (R13). Then, in the same transaction, `releaseFrom()`
   runs `UPDATE time_entries SET invoice_id = NULL WHERE invoice_id = ?`, and `delete()` removes the
   invoice; `cascade = ALL` removes its lines first. Because of `on delete restrict`, forgetting the
   release would make PostgreSQL refuse the delete.

```java
    this.clock = clock;
  }

  @GetMapping
  public String index(Model model) {
    model.addAttribute("invoices", invoices.findAll());
    return "invoices/index";
  }

  @GetMapping("/new")
  public String create(Model model) {
    InvoiceForm form = new InvoiceForm();
    form.setUpTo(LocalDate.now(clock));
    return showForm(form, model);
  }

  @PostMapping
  public String store(
      @Valid @ModelAttribute("form") InvoiceForm form,
      BindingResult binding,
      Model model,
      RedirectAttributes redirect) {
    if (binding.hasErrors()) {
      return showForm(form, model);
    }
    try {
      Invoice invoice = invoices.generate(form.getClientId(), form.getUpTo());
      redirect.addFlashAttribute(
          "status", "Invoice %s was created as a draft.".formatted(invoice.getNumber()));
      return "redirect:/invoices/" + invoice.getId();
    } catch (InvoicingException e) {
      model.addAttribute("error", e.getMessage());
      return showForm(form, model);
    }
  }

  @GetMapping("/{id}")
  public String show(@PathVariable Long id, Model model) {
    model.addAttribute("invoice", invoices.getWithLines(id));
    return "invoices/show";
  }

  @PostMapping("/{id}/send")
  public String send(@PathVariable Long id, RedirectAttributes redirect) {
    try {
      Invoice invoice = invoices.send(id);
      redirect.addFlashAttribute(
          "status", "Invoice %s was marked as sent.".formatted(invoice.getNumber()));
    } catch (InvoicingException e) {
      redirect.addFlashAttribute("error", e.getMessage());
    }
    return "redirect:/invoices/" + id;
  }

  @PostMapping("/{id}/mark-paid")
  public String markPaid(@PathVariable Long id, RedirectAttributes redirect) {
    try {
      Invoice invoice = invoices.markPaid(id);
      redirect.addFlashAttribute(
          "status", "Invoice %s was marked as paid.".formatted(invoice.getNumber()));
    } catch (InvoicingException e) {
      redirect.addFlashAttribute("error", e.getMessage());
    }
    return "redirect:/invoices/" + id;
  }

  @PostMapping("/{id}/delete")
  public String delete(@PathVariable Long id, RedirectAttributes redirect) {
    try {
      String number = invoices.delete(id);
      redirect.addFlashAttribute(
          "status",
          "Draft %s was deleted. Its time entries can be invoiced again.".formatted(number));
      return "redirect:/invoices";
    } catch (InvoicingException e) {
      redirect.addFlashAttribute("error", e.getMessage());
      return "redirect:/invoices/" + id;
    }
  }

  private String showForm(InvoiceForm form, Model model) {
    model.addAttribute("form", form);
    model.addAttribute("clients", invoices.clientsForSelect());
    model.addAttribute("today", LocalDate.now(clock));
    return "invoices/new";
  }
}
```

**What happens:**

1. `@Valid @ModelAttribute("form")` binds the request parameters `clientId` and `upTo` into the form and
   validates the **shape**. `@DateTimeFormat(iso = DATE)` parses `2026-09-30` from `<input type="date">`.
2. Business rules (nothing to invoice, overlap) come back as `InvoicingException`. We re-render the form
   with the message; the form keeps the user's choices because it is the same object.
3. Success → redirect (Post/Redirect/Get, lesson 05): refreshing the page does not generate a second
   invoice. `status` is the flash attribute your layout's flash box already shows (use the name
   you chose in lesson 05).
4. Every change is a `POST` (`/send`, `/mark-paid`, `/delete`), as in lesson 05 — a `GET` link must
   never change data.
5. Only `InvoicingException` is caught. A database failure is not the user's problem to fix; it goes to
   the error page and the log.

### `@PastOrPresent` must use our `Clock`

`@PastOrPresent` asks Hibernate Validator for "now", and by default the validator reads the **JVM's
system clock** — not our `Clock` bean. The controller says "today" is 30 September 2026 in a test with a
fixed clock, but the validator would compare `upTo` with the real date. A test that posts
`2026-09-30` would then pass or fail depending on the day you run it.

Jakarta Validation has a hook for this, `ClockProvider`, and Spring Boot lets you set it with a
`ValidationConfigurationCustomizer` bean. Add it to `ClockConfig`:

```java
// src/main/java/ee/ta25/billable/common/ClockConfig.java — add inside the class
  /** Makes {@code @PastOrPresent} and the other date constraints use the same Clock as the app. */
  @Bean
  public ValidationConfigurationCustomizer validationClock(Clock clock) {
    return configuration -> configuration.clockProvider(() -> clock);
  }
```

(Add `import org.springframework.boot.validation.autoconfigure.ValidationConfigurationCustomizer;`.)

**What happens:**

1. Spring Boot builds the validator once at start-up and calls every `ValidationConfigurationCustomizer`
   bean on the way. `clockProvider(...)` takes a `ClockProvider`, which has one method `getClock()` —
   so a lambda `() -> clock` is enough.
2. The `clock` parameter is whichever `Clock` bean wins injection: the real Tallinn clock in the app, a
   `@Primary` fixed clock in tests (lesson 14). Now the form and the controller agree on "today".
3. In Spring Boot 4 the class lives in `org.springframework.boot.validation.autoconfigure` (it comes with
   `spring-boot-starter-validation`, in your `pom.xml` since lesson 01). Spring Boot 3 tutorials import it
   from `org.springframework.boot.autoconfigure.validation` — that package no longer exists in Boot 4.

## Step 11 — A Mockito test for the generator

The full end-to-end test against PostgreSQL comes in lesson 14. Today we test the **orchestration**
with Mockito (lesson 12): repositories and the number generator are mocked, the pure pieces
(`OverlapDetector`, `TimeRounding`, `DueDateCalculator`) are real, and the `Clock` is fixed.

The entities (`Client`, `Project`, `TimeEntry`) are **real objects**, not mocks. Lesson 12 called a
mocked entity an over-mocking smell: an entity is plain data, and a mock of it only repeats getters.
`ProjectTestData` (lessons 11–12) builds the project with an id; for a `TimeEntry` we use its lesson 06
constructor and set the id with `ReflectionTestUtils`, as `ProjectTestData.withId()` does.

```java
@ExtendWith(MockitoExtension.class)
class InvoiceGeneratorTest {

  private static final Clock CLOCK =
      Clock.fixed(Instant.parse("2026-09-30T09:00:00Z"), ClockConfig.ZONE);
  private static final LocalDate UP_TO = LocalDate.parse("2026-09-30");

  @Mock private TimeEntryRepository timeEntries;
  @Mock private InvoiceRepository invoices;
  @Mock private InvoiceLineRepository invoiceLines;
  @Mock private InvoiceNumberGenerator numbers;
```

**What happens:**

1. `Clock.fixed(2026-09-30T09:00Z, ClockConfig.ZONE)` — 12:00 in Tallinn (`Europe/Tallinn`, the zone
   constant from lesson 10) on 30 September. The settings are a plain `new BillableProperties(...)`:
   a record is just data, so the test builds one with VAT `2400`, as `application.properties` would.
   (Only `vatRateBp` matters here; the other components are filled with harmless values.) The invoice
   year is 2026, the issue date 30.09, the due date (a Wednesday + 14 days) 14.10.
2. `when(timeEntries.findInvoiceable(client, BEFORE, BillingType.INTERNAL))` also checks the generator asks for "before
   midnight of 1 October" — if you get the boundary wrong, the stub does not match and the list is
   empty, so the test fails with `NothingToInvoiceException`.
3. The strategy stub only answers for **exactly** 135 minutes and 0 € already billed. So this test
   proves rounding per entry (70 → 75) and summing (75 + 60 = 135) without looking inside the strategy.
4. `thenAnswer(call -> call.getArgument(0))` makes `save()` return the invoice it was given, as a real
   repository would.
5. `first.getInvoice()` is the new invoice: each real entry was linked to it by `assignTo()`.
6. The overlap test uses `verify(..., never())` — the "it did **not** happen" assertion from lesson 12.
   No number was taken and nothing was saved.
7. What this test **cannot** prove: that the SQL is right, that the transaction really rolls back, that
   the unique constraint works. That needs a real database — lesson 14.

## Troubleshooting

| Error | Cause | Fix |
|---|---|---|
| `Schema-validation: missing table [invoices]` | Migration did not run: wrong folder, single underscore (`V6_create…`), or wrong version | File must be `db/migration/V6__create_invoices.sql` (two underscores) |
| `Found more than one migration with version 6` | Your numbering already used 6 | Rename the new files to the next free numbers before they run |
| `Schema-validation: wrong column type encountered in column [subtotal_cents] in table [invoices]; found [int4 (Types#INTEGER)], but expecting [bigint (Types#BIGINT)]` | The migration says `integer` but the field is `long` (or the other way round) | Money columns are `bigint` ↔ `long`; `minutes`/`vat_rate_bp` are `integer` ↔ `int` |
| `not-null property references a null or transient value: InvoiceLine.invoice` | `lines.add(line)` without setting `line.invoice` | Always use `invoice.addLine(line)` |
| `LazyInitializationException: could not initialize proxy [ee.ta25.billable.client.Client#1] - no Session` | A template reads a lazy relation that was not loaded | Use the `@EntityGraph` repository methods from Step 3 |
| `UnexpectedRollbackException: Transaction silently rolled back because it has been marked as rollback-only` | You caught an `InvoicingException` **inside** a `@Transactional` method and carried on | Catch it in the controller (outside the transaction), as in Step 9 |
| `ERROR: update or delete on table "invoices" violates foreign key constraint "time_entries_invoice_id_fkey"` | Invoice deleted without releasing entries | Delete through `InvoiceService.delete()` |
| `duplicate key value violates unique constraint "invoices_number_key"` | Two invoices generated at the same moment | Expected with max + 1 — fixed in lesson 14 |
| `UnnecessaryStubbingException` | Strict stubs: a stub was never used | Remove the stub. Build entities as real objects (`ProjectTestData`, constructors) instead of stubbing their getters |
| `Cannot resolve method 'calculate(Project, int, Money)'` | Strategy still has the lesson 08 `long` signature | Lesson 10 changed strategies to take and return `Money` |
| Status saved as `DRAFT` (capitals) | `@EnumeratedValue` missing on `InvoiceStatus.dbValue` | Add it (Step 2) |
| `Schema-validation: wrong column type encountered in column [status]` | `@Enumerated(EnumType.STRING)` missing on `Invoice.status`, so JPA maps the ordinal | Add it (Step 3) |

- **Entities:** `Invoice` with `@OneToMany(mappedBy, cascade = ALL, orphanRemoval = true)` and `addLine()`; `InvoiceLine`; `TimeEntry.invoice`; `InvoiceStatus` stored via `@EnumeratedValue`.
- **Repositories:** `findInvoiceable` with `join fetch`, a `GROUP BY` constructor-expression query, `findMaxNumberLike`, `@EntityGraph` for pages, a `@Modifying` bulk update.
- **Pure pieces:** `TimeSlot`, `Overlap`, `OverlapDetector` (sort + sweep), `InvoiceNumberGenerator.format()`/`sequenceOf()` — with parameterized tests.
- **Orchestrator:** `InvoiceGenerator.generate()` in one `@Transactional` method; dirty checking marks the entries.
- **Rules as exceptions:** `InvoicingException` subclasses with messages a user can act on.
- **Service and web:** `InvoiceService`, the R14 guard, `InvoiceController` (POST for every change), three templates.
- **Mockito test** with a fixed `Clock`; the database-backed test follows in lesson 14.

<summary>Task 3 — Discount with largest-remainder allocation (Intermediate)</summary>

**1. `Money.allocate()`** — add to `common/Money.java` (imports: `java.util.Arrays`,
`java.util.Comparator`, `java.util.List`, `java.util.stream.IntStream`):

```java
// src/main/java/ee/ta25/billable/common/Money.java (add inside the record)
/**
 * Splits this amount into parts proportional to {@code ratios}; the parts always add up to exactly
 * this amount (largest remainder method).
 */
public List<Money> allocate(long... ratios) {
  if (ratios.length == 0) {
    throw new IllegalArgumentException("At least one ratio is required");
  }
  long total = 0;
  for (long ratio : ratios) {
    if (ratio < 0) {
      throw new IllegalArgumentException("Ratios must not be negative");
    }
    total += ratio;
  }
  if (total == 0) {
    throw new IllegalArgumentException("Ratios must not all be zero");
  }
  if (cents < 0) {
    throw new IllegalArgumentException("Only non-negative amounts can be allocated");
  }

  long[] shares = new long[ratios.length];
  long[] remainders = new long[ratios.length];
  long allocated = 0;
  for (int i = 0; i < ratios.length; i++) {
    long exact = Math.multiplyExact(cents, ratios[i]); // the true share is exact / total
    shares[i] = exact / total; // rounded down
    remainders[i] = exact % total; // what rounding down threw away
    allocated += shares[i];
  }

  long left = cents - allocated; // always smaller than ratios.length
  List<Integer> byLargestRemainder =
      IntStream.range(0, ratios.length)
          .boxed()
          .sorted(
              Comparator.comparingLong((Integer i) -> remainders[i])
                  .reversed()
                  .thenComparing(i -> i))
          .toList();
  for (int k = 0; k < left; k++) {
    shares[byLargestRemainder.get(k)]++;
  }
  return Arrays.stream(shares).mapToObj(Money::fromCents).toList();
}
```

Every part first gets its share rounded **down**; the few cents lost that way go one by one to the
parts with the largest remainders (ties: the earlier part). All integer maths; `multiplyExact` throws
instead of overflowing.

<summary>Task 4 — Measure naive vs sweep (Advanced)</summary>

A benchmark is not a test, so it is a `main` method in the test sources (it can see the production
classes, but it is not packaged into the application). Run it from the IDE.

```java
// src/test/java/ee/ta25/billable/invoice/OverlapBenchmark.java
package ee.ta25.billable.invoice;

import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Optional;
import java.util.Random;

/** Compares naive O(n²) and sort-and-sweep overlap detection. Not a unit test. */
public class OverlapBenchmark {

  public static void main(String[] args) {
    OverlapDetector detector = new OverlapDetector();
    System.out.printf("%8s %14s %12s %12s%n", "n", "naive pairs", "naive ms", "sweep ms");

    for (int n : List.of(100, 1_000, 10_000)) {
      List<TimeSlot> slots = slots(n);
      for (int i = 0; i < 5; i++) { // warm-up: let the JIT compiler optimise both versions
        naive(slots);
        detector.find(slots);
      }

      long start = System.nanoTime();
      naive(slots);
      double naiveMs = (System.nanoTime() - start) / 1e6;

      start = System.nanoTime();
      detector.find(slots);
      double sweepMs = (System.nanoTime() - start) / 1e6;

      System.out.printf("%8d %14d %12.2f %12.2f%n", n, (long) n * (n - 1) / 2, naiveMs, sweepMs);
    }
  }

  /** 45-minute slots with 15-minute gaps, shuffled: no overlaps, so nothing returns early. */
  private static List<TimeSlot> slots(int n) {
    List<TimeSlot> slots = new ArrayList<>(n);
    LocalDateTime time = LocalDateTime.parse("2026-01-01T08:00");
    for (int i = 1; i <= n; i++) {
      LocalDateTime end = time.plusMinutes(45);
      slots.add(new TimeSlot(i, time, end, "Entry " + i));
      time = end.plusMinutes(15);
    }
    Collections.shuffle(slots, new Random(42));
    return slots;
  }

  private static Optional<Overlap> naive(List<TimeSlot> slots) {
    for (int i = 0; i < slots.size(); i++) {
      for (int j = i + 1; j < slots.size(); j++) {
        if (slots.get(i).overlaps(slots.get(j))) {
          return Optional.of(new Overlap(slots.get(i), slots.get(j)));
        }
      }
    }
    return Optional.empty();
  }
}
```

On the teacher's laptop:

| n | naive pairs | naive | sweep |
|---|---|---|---|
| 100 | 4,950 | 0.4 ms | 0.07 ms |
| 1,000 | 499,500 | 2.5 ms | 0.5 ms |
| 10,000 | 49,995,000 | 458 ms | 3.4 ms |

From 1,000 to 10,000 entries the naive time grows far faster than the sweep time — the n² shape. Small
inputs are noisy (JIT compilation, garbage collection); that is why there is a warm-up and why only the
large sizes tell you much. The data has no overlaps on purpose: with an overlap both versions return
early, and you would measure where the overlap happens to be, not the algorithm.

> **The professional tool.** A hand-made `nanoTime()` loop is fine for seeing the *shape* of the growth.
> For numbers you would publish, Java has **JMH** (Java Microbenchmark Harness, from the OpenJDK team):
> you annotate a method with `@Benchmark`, and JMH handles warm-up, many iterations, dead-code
> elimination and statistics for you. It needs its own Maven setup, which is why we do not use it here.
