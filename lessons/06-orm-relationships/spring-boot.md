## What we build today

- Two Flyway migrations: `time_entries`, then `tags` + `tag_time_entry`.
- Entities `timeentry.TimeEntry` (`@ManyToOne(fetch = LAZY)` to `Project`, `@ManyToMany` to `Tag` as
  the owning side, `Set<Tag>`) and `timeentry.Tag`; repositories for both.
- A seeder with about 60 time entries over the last three weeks, some with tags.
- The time sheet page `/time-entries`: first written naively (it **crashes** with
  `open-in-view=false` — and we explain why that is good), then measured with `open-in-view=true`
  (about 60 queries), then fixed with an entity graph (2 queries).
- A form to log a new time entry, validated by R4 with `@AssertTrue` methods.

**Final result:** the navigation has a "Time sheet" link. The page shows the latest 50 entries with date,
time, project, client, description, duration as `h:mm` and tags, using two SQL statements no matter how
many entries exist.

This builds on lesson 05: `client.Client`, `project.Project` (with `client` as a lazy `@ManyToOne`,
`archivedAt` as `LocalDateTime`), the repositories, `common.Formatters` and the layout (`layout.html`). In
`application.properties` you have had `spring.jpa.hibernate.ddl-auto=validate` and
`spring.jpa.open-in-view=false` since lesson 03.

## Step 1 — Flyway migrations

Flyway runs SQL files from `src/main/resources/db/migration` in version order, once each. Use the **next
free version numbers**. This guide assumes you have `V1__create_clients.sql` and
`V2__create_projects.sql`. If you did the lesson 03 independent task, `V3__add_rounding_minutes_check.sql`
already exists — then name the files below **`V4__...` and `V5__...`**. Never change a migration that has
already run — add a new one.

```sql
-- src/main/resources/db/migration/V3__create_time_entries.sql
CREATE TABLE time_entries (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    project_id  BIGINT       NOT NULL,
    started_at  TIMESTAMP    NOT NULL,
    ended_at    TIMESTAMP    NOT NULL,
    description VARCHAR(255) NOT NULL,
    billable    BOOLEAN      NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMP    NOT NULL,
    updated_at  TIMESTAMP    NOT NULL,
    CONSTRAINT time_entries_project_id_foreign
        FOREIGN KEY (project_id) REFERENCES projects (id) ON DELETE RESTRICT
);

CREATE INDEX time_entries_project_id_started_at_index ON time_entries (project_id, started_at);
```

```sql
-- src/main/resources/db/migration/V4__create_tags.sql
CREATE TABLE tags (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name       VARCHAR(40) NOT NULL,
    created_at TIMESTAMP   NOT NULL,
    updated_at TIMESTAMP   NOT NULL,
    CONSTRAINT tags_name_unique UNIQUE (name)
);

CREATE TABLE tag_time_entry (
    tag_id        BIGINT NOT NULL,
    time_entry_id BIGINT NOT NULL,
    CONSTRAINT tag_time_entry_pkey PRIMARY KEY (tag_id, time_entry_id),
    CONSTRAINT tag_time_entry_tag_id_foreign
        FOREIGN KEY (tag_id) REFERENCES tags (id) ON DELETE CASCADE,
    CONSTRAINT tag_time_entry_time_entry_id_foreign
        FOREIGN KEY (time_entry_id) REFERENCES time_entries (id) ON DELETE CASCADE
);

CREATE INDEX tag_time_entry_time_entry_id_index ON tag_time_entry (time_entry_id);
```

**What happens:**

1. The same style as V1 and V2: an identity primary key, named constraints, and `created_at` /
   `updated_at` filled by Hibernate (`@CreationTimestamp` / `@UpdateTimestamp`).
   `FOREIGN KEY ... ON DELETE RESTRICT` — PostgreSQL refuses to delete a project that still has time
   entries. Time entries are billing evidence (README, concept 2).
2. `TIMESTAMP` (without time zone) stores the local time as typed, e.g. `2026-09-30 09:00`. Billable is a
   single-user application in Europe/Tallinn, so local times are what we want; in Java this maps to
   `LocalDateTime`.
3. The composite index `(project_id, started_at)` serves "entries of project X in a date range" — the
   query behind invoices (lesson 13) and budget checks (lesson 09). PostgreSQL does not index foreign-key
   columns automatically.
4. The pivot table has **no `id`**. The pair `(tag_id, time_entry_id)` is the primary key, so a tag cannot
   be attached twice to one entry. `ON DELETE CASCADE` on both sides removes link rows together with an
   entry or a tag.
5. The extra index on `time_entry_id`: the primary key starts with `tag_id`, so it cannot help the query
   "tags of these entries", which the time sheet runs on every page view.
6. The table names are identical to the Laravel track (`tag_time_entry` is Laravel's naming convention).

**Check it works:** start the application (`./mvnw spring-boot:run -Dspring-boot.run.profiles=dev`).
The log shows

```java
// src/main/java/ee/ta25/billable/timeentry/TimeEntry.java
package ee.ta25.billable.timeentry;

import ee.ta25.billable.project.Project;
import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.FetchType;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.JoinColumn;
import jakarta.persistence.JoinTable;
import jakarta.persistence.ManyToMany;
import jakarta.persistence.ManyToOne;
import jakarta.persistence.Table;
import java.time.Duration;
import java.time.LocalDateTime;
import java.util.Collection;
import java.util.HashSet;
import java.util.Set;
import org.hibernate.annotations.CreationTimestamp;
import org.hibernate.annotations.UpdateTimestamp;

@Entity
@Table(name = "time_entries")
public class TimeEntry {

  @Id
  @GeneratedValue(strategy = GenerationType.IDENTITY)
  private Long id;

  @ManyToOne(fetch = FetchType.LAZY, optional = false)
  @JoinColumn(name = "project_id", nullable = false)
  private Project project;

  @Column(name = "started_at", nullable = false)
  private LocalDateTime startedAt;

  @Column(name = "ended_at", nullable = false)
  private LocalDateTime endedAt;

  @Column(nullable = false, length = 255)
  private String description;

  @Column(nullable = false)
  private boolean billable = true;

  /** Owning side of the many-to-many: this field decides the rows in tag_time_entry. */
  @ManyToMany
  @JoinTable(
      name = "tag_time_entry",
      joinColumns = @JoinColumn(name = "time_entry_id"),
      inverseJoinColumns = @JoinColumn(name = "tag_id"))
  private Set<Tag> tags = new HashSet<>();

  @CreationTimestamp
  @Column(name = "created_at", nullable = false, updatable = false)
  private LocalDateTime createdAt;

  @UpdateTimestamp
  @Column(name = "updated_at", nullable = false)
  private LocalDateTime updatedAt;

  protected TimeEntry() {}

  public TimeEntry(
      Project project,
      LocalDateTime startedAt,
      LocalDateTime endedAt,
      String description,
      boolean billable) {
    this.project = project;
    this.startedAt = startedAt;
    this.endedAt = endedAt;
    this.description = description;
    this.billable = billable;
  }

  /** Length in whole minutes, not rounded (rounding rules come in lesson 10). */
  public long durationMinutes() {
    return Duration.between(startedAt, endedAt).toMinutes();
  }

  /** Makes the entry's tags exactly the given ones. */
  public void replaceTags(Collection<Tag> newTags) {
    tags.clear();
    tags.addAll(newTags);
  }

  public Long getId() {
    return id;
  }

  public Project getProject() {
    return project;
  }

  public LocalDateTime getStartedAt() {
    return startedAt;
  }

  public LocalDateTime getEndedAt() {
    return endedAt;
  }

  public String getDescription() {
    return description;
  }

  public boolean isBillable() {
    return billable;
  }

  /** The owning side: changes to this set are saved to tag_time_entry. */
  public Set<Tag> getTags() {
    return tags;
  }
}
```

**What happens:**

1. `@ManyToOne(fetch = FetchType.LAZY, optional = false)` — the **default** for `@ManyToOne` is EAGER,
   which would load the project (and, through it, maybe more) on every query. Always write `LAZY`.
   `optional = false` tells Hibernate the column is never null.
2. Hibernate fills a lazy `project` with a **proxy**: an object of a generated subclass of `Project` that
   knows only the id. The first call like `getName()` runs the SQL — but only while a session is open.
3. `@ManyToMany` + `@JoinTable` makes `TimeEntry.tags` the **owning side**: Hibernate writes
   `tag_time_entry` rows from this set. We do **not** map `Tag.timeEntries` (the inverse side), because
   Billable never navigates from a tag to its entries as a Java collection (README, concept 4). So there
   is nothing to keep in sync.
4. `Set<Tag>`, not `List<Tag>`: a tag can appear only once per entry, which matches the primary key. A
   `Set` needs correct `equals`/`hashCode`. The default (object identity) breaks when the same tag is loaded
   in two different sessions: the set would contain "two" `meeting` tags. We use the **name** — unique and
   stable — as the business key. `tag.getName()` (not `tag.name`) matters: if `other` is a Hibernate
   proxy, its fields are empty and only the getter loads the real value.
5. `getTags()` returns the set itself. Because this is the owning side, adding or removing tags in it
   (`entry.getTags().addAll(...)`) is written to `tag_time_entry` on save. `replaceTags(...)` is a
   convenience for "exactly these tags".
6. `replaceTags()` is the JPA version of Laravel's `sync()`: Hibernate compares the set before and after
   and writes the differences to `tag_time_entry` when the entity is saved.
7. `@CreationTimestamp` / `@UpdateTimestamp` fill the timestamps; `ddl-auto=validate` checks at startup
   that every mapped column exists with a compatible type.

## Step 3 — Seed 60 time entries

The seeder runs when the application starts and does nothing if entries already exist.

```java
// src/main/java/ee/ta25/billable/timeentry/TimeEntrySeeder.java
package ee.ta25.billable.timeentry;

import ee.ta25.billable.project.ProjectRepository;
import java.time.DayOfWeek;
import java.time.LocalDate;
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Random;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.CommandLineRunner;
import org.springframework.context.annotation.Profile;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;

/** Development data: 60 time entries over the last three full weeks. */
@Component
@Profile("dev")
@Order(3)
public class TimeEntrySeeder implements CommandLineRunner {

  private static final Logger log = LoggerFactory.getLogger(TimeEntrySeeder.class);

  private static final List<String> TAG_NAMES =
      List.of("meeting", "bugfix", "design", "review", "support");

  private static final List<String> DESCRIPTIONS =
      List.of(
          "Kick-off call",
          "Fix login bug",
          "Code review",
          "Design home page",
          "Write API documentation",
          "Weekly meeting",
          "Deploy to staging",
          "Answer support tickets");

  /** Possible entry lengths in minutes. */
  private static final int[] LENGTHS = {30, 45, 60, 90, 120};

  private final TimeEntryRepository timeEntries;
  private final ProjectRepository projects;
  private final TagRepository tags;

  public TimeEntrySeeder(
      TimeEntryRepository timeEntries, ProjectRepository projects, TagRepository tags) {
    this.timeEntries = timeEntries;
    this.projects = projects;
    this.tags = tags;
  }

  @Override
  public void run(String... args) {
    if (timeEntries.count() > 0) {
      return;
    }
    var activeProjects = projects.findByArchivedAtIsNullOrderByNameAsc();
    if (activeProjects.isEmpty()) {
      log.warn("No active projects yet, skipping time entry seeding.");
      return;
    }

    var tagList =
        TAG_NAMES.stream()
            .map(name -> tags.findByName(name).orElseGet(() -> tags.save(new Tag(name))))
            .toList();

    var random = new Random(42); // same "random" data every time
    var monday = LocalDate.now().minusWeeks(3).with(DayOfWeek.MONDAY);
    var entries = new ArrayList<TimeEntry>();

    for (int day = 0; day < 21; day++) {
      var date = monday.plusDays(day);
      if (date.getDayOfWeek() == DayOfWeek.SATURDAY || date.getDayOfWeek() == DayOfWeek.SUNDAY) {
        continue;
      }
      var start = date.atTime(9, 0);
      for (int slot = 0; slot < 4; slot++) {
        var minutes = LENGTHS[random.nextInt(LENGTHS.length)];
        var entry =
            new TimeEntry(
                activeProjects.get(random.nextInt(activeProjects.size())),
                start,
                start.plusMinutes(minutes),
                DESCRIPTIONS.get(random.nextInt(DESCRIPTIONS.size())),
                random.nextInt(6) != 0); // about 1 in 6 is not billable

        var chosenTags = new HashSet<Tag>();
        for (int i = random.nextInt(3); i > 0; i--) {
          chosenTags.add(tagList.get(random.nextInt(tagList.size())));
        }
        entry.replaceTags(chosenTags);

        entries.add(entry);
        start = start.plusMinutes(minutes + 15L); // 15 min break
      }
    }

    timeEntries.saveAll(entries);
    log.info("Seeded {} time entries.", entries.size());
  }
}
```

**What happens:**

1. Like `common.DevDataSeeder` from lesson 03, this is a `CommandLineRunner` that runs only with the
   `dev` profile. `DevDataSeeder` has `@Order(1)` and creates the 3 clients and 7 projects; this one has
   `@Order(3)`, so it runs **after** it and adds entries to that data. (`@Order(2)` was the temporary
   `QueryPlayground` from lesson 03.)
2. `DevDataSeeder` skips when clients exist; this seeder skips when **time entries** exist. So on your
   existing database (which already has clients) it still adds the entries once, and a restart does not
   add them again.
3. `LocalDate.now().minusWeeks(3).with(DayOfWeek.MONDAY)` is the Monday three weeks ago. 21 days minus
   6 weekend days = 15 working days × 4 entries = 60 entries.
4. `new Random(42)` gives the same sequence every time, so everyone in class gets the same data.
5. `saveAll(entries)` saves all 60 in **one** transaction. The projects and tags are *detached* (their
   sessions closed after the repository calls) but they have ids, so Hibernate just writes their ids into
   `project_id` and `tag_time_entry`.

**Check it works:** restart the app with the `dev` profile. The log shows `Seeded 60 time entries.`
Restart again: no new message, no duplicates.


## Step 6 — Measure: what open-in-view would hide

To see the N+1 problem with our own eyes, we **temporarily** switch open-in-view on and turn on SQL
logging and statistics. Add to `src/main/resources/application.properties`:

```properties
# src/main/resources/application.properties
# --- TEMPORARY for step 6: set back to false in step 7 ---
spring.jpa.open-in-view=true

# Statistics: a summary per Hibernate session (keep this while developing)
spring.jpa.properties.hibernate.generate_statistics=true
```

(Change the existing `open-in-view` line instead of adding a second one. SQL logging —
`logging.level.org.hibernate.SQL=debug` and the `bind=trace` line — is already on since lesson 03, in
`application-dev.properties`; run with the `dev` profile as usual.)

**What happens:**

1. With `open-in-view=true`, Spring opens a Hibernate session at the start of the request and closes it
   after the view is rendered. Lazy loading in the template now "just works" — silently.
2. The count is **1 + P + C + 50**: one query for the entries, one per **distinct** project (P), one per
   **distinct** client (C), and one tag query per entry. With 6 projects and 3 clients: 1 + 6 + 3 + 50 = 60.
3. Why "per distinct project" and not "per entry" (Laravel gets 151)? The Hibernate session is an
   **identity map**: project 3 is loaded once, and every other entry of project 3 gets the same object.
   The tags are a different collection for every entry, so they cost one query each.
4. More entries on the page → more tag queries. That growth is the N+1 problem.
5. If you do **not** set the property at all, Spring Boot warns at startup:
   `spring.jpa.open-in-view is enabled by default. Therefore, database queries may be performed during view rendering.`
   You set it to `true` explicitly, so Boot assumes you know what you are doing and stays quiet.

Write down your number.

## Step 7 — Fix it: load what the page needs, in the query

First, set open-in-view **back to false** in `application.properties`:

```properties
# src/main/resources/application.properties
spring.jpa.open-in-view=false
```

**The tempting fix — and why it is a trap.** You could put an entity graph on the existing method:

```java
// DON'T — shown only to explain the problem
@EntityGraph(attributePaths = {"project", "project.client", "tags"})
List<TimeEntry> findTop50ByOrderByStartedAtDesc();
```

It works and the log shows one query — plus this warning:

```
WARN  ... HHH90003004: firstResult/maxResults specified with collection fetch; applying in memory
```

Joining the `tags` **collection** gives one SQL row per tag, so the database cannot apply "first 50
entries". Hibernate loads **all** entries with all their tags and cuts the list to 50 in Java. With 60
entries you do not notice. With 100 000 entries the page loads 100 000 rows to show 50. (You can make this
a hard error with `spring.jpa.properties.hibernate.query.fail_on_pagination_over_collection_fetch=true`.)

**The correct fix: two queries.** First the ids of the 50 latest entries (with a real `LIMIT`), then those
entries with all their relations (no `LIMIT` needed). Replace `TimeEntryRepository` with:

```java
// src/main/java/ee/ta25/billable/timeentry/TimeEntryRepository.java
package ee.ta25.billable.timeentry;

import java.util.Collection;
import java.util.List;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.EntityGraph;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

public interface TimeEntryRepository extends JpaRepository<TimeEntry, Long> {

  int TIME_SHEET_SIZE = 50;

  /** The latest 50 entries with project, client and tags: always two SQL statements. */
  default List<TimeEntry> findAllForTimeSheet() {
    var ids = findLatestIds(PageRequest.of(0, TIME_SHEET_SIZE));
    return ids.isEmpty() ? List.of() : findWithDetailsByIdIn(ids);
  }

  /** Ids of the latest entries. The page size becomes a real LIMIT in SQL. */
  @Query("select e.id from TimeEntry e order by e.startedAt desc")
  List<Long> findLatestIds(Pageable pageable);

  /** The given entries with project, client and tags, in one query. */
  @EntityGraph(attributePaths = {"project", "project.client", "tags"})
  @Query("select e from TimeEntry e where e.id in :ids order by e.startedAt desc")
  List<TimeEntry> findWithDetailsByIdIn(@Param("ids") Collection<Long> ids);
}
```

Change `index()` in the controller:

```java
// src/main/java/ee/ta25/billable/timeentry/TimeEntryController.java (index)
@GetMapping
public String index(Model model) {
  model.addAttribute("entries", timeEntries.findAllForTimeSheet());
  return "time-entries/index";
}
```

Restart and reload `/time-entries`.

**What happens:**

1. `findAllForTimeSheet()` is a **default method** in the repository interface: normal Java code that
   Spring Data leaves alone. It combines the two query methods below, so callers (the controller now, a
   service in lesson 07) need only one call. `TIME_SHEET_SIZE` is a constant (fields in an interface are
   automatically `public static final`).
2. `findLatestIds(PageRequest.of(0, 50))` — `@Query` returns only `e.id`. Spring Data adds
   `fetch first 50 rows only` (PostgreSQL's standard form of `LIMIT 50`). A small, fast query that can use
   an index.
3. `findWithDetailsByIdIn(ids)` — the `@EntityGraph` tells Hibernate to fetch `project`, `project.client`
   (dot = nested) and `tags` in the **same** SQL statement, with joins. The result has one row per
   entry-tag pair; Hibernate builds 50 `TimeEntry` objects from it, each with its project, client and tag
   set filled.
4. No `LIMIT` is needed in the second query — the ids already limit it — so there is no in-memory
   pagination.
5. `ids.isEmpty()` — with no entries we skip the second query; an empty `IN ()` list is not useful.
6. The template does not change at all. Everything it touches is loaded, so there is no
   `LazyInitializationException` even with open-in-view off.

**Check it works:** the page looks exactly like in step 6, and the log shows **two** `org.hibernate.SQL`
lines for the request:

```
DEBUG org.hibernate.SQL : select te1_0.id from time_entries te1_0 order by te1_0.started_at desc fetch first ? rows only
DEBUG org.hibernate.SQL : select te1_0.id,te1_0.billable,...,p1_0.id,...,c1_0.id,...,t1_1.id,t1_1.name,...
                          from time_entries te1_0 join projects p1_0 on ... join clients c1_0 on ...
                          left join tag_time_entry t1_0 on ... left join tags t1_1 on ...
                          where te1_0.id in (?,?,?,...) order by te1_0.started_at desc
```

With open-in-view off, each repository call has its own session, so you see **two** `Session Metrics`
blocks with 1 statement each. **From about 60 statements to 2** — and it stays 2 for any number of
entries. (The advanced task adds a per-request counter.)

Other options you should know:

- `join fetch` in JPQL does the same as the entity graph:
  `select e from TimeEntry e join fetch e.project p join fetch p.client left join fetch e.tags where e.id in :ids`.
- `@BatchSize(size = 50)` on the `tags` field (or `spring.jpa.properties.hibernate.default_batch_fetch_size=50`)
  loads the tags of up to 50 entries in one `IN (...)` query when the first one is touched. It needs an
  **open session**, so it helps inside a `@Transactional` service method (lesson 07), not in a template
  with open-in-view off.

## Step 8 — Log a new time entry (R4)

The form class. R4 compares **two** fields, so a single-field annotation cannot express it. We use
`@AssertTrue` on methods: Jakarta Validation calls them like getters and reports an error when they return
`false`.

```java
// src/main/java/ee/ta25/billable/timeentry/TimeEntryForm.java
package ee.ta25.billable.timeentry;

import jakarta.validation.constraints.AssertTrue;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Size;
import java.time.Duration;
import java.time.LocalDateTime;
import org.springframework.format.annotation.DateTimeFormat;

/** What the time entry form sends. */
public class TimeEntryForm {

  /** The format of an HTML datetime-local input: 2026-09-30T09:00 */
  private static final String INPUT_FORMAT = "yyyy-MM-dd'T'HH:mm";

  private static final Duration MAX_LENGTH = Duration.ofHours(12);

  @NotNull(message = "Choose a project.")
  private Long projectId;

  @NotNull(message = "Start is required.")
  @DateTimeFormat(pattern = INPUT_FORMAT)
  private LocalDateTime startedAt;

  @NotNull(message = "End is required.")
  @DateTimeFormat(pattern = INPUT_FORMAT)
  private LocalDateTime endedAt;

  @NotBlank(message = "Description is required.")
  @Size(max = 255, message = "Description can be at most 255 characters.")
  private String description;

  private boolean billable = true;

  /** R4: the entry must end after it starts. */
  @AssertTrue(message = "The end must be after the start.")
  public boolean isEndAfterStart() {
    return startedAt == null || endedAt == null || endedAt.isAfter(startedAt);
  }

  /** R4: an entry can be at most 12 hours long (exactly 12 h is allowed). */
  @AssertTrue(message = "A time entry can be at most 12 hours long.")
  public boolean isAtMostTwelveHours() {
    return startedAt == null
        || endedAt == null
        || Duration.between(startedAt, endedAt).compareTo(MAX_LENGTH) <= 0;
  }

  public Long getProjectId() {
    return projectId;
  }

  public void setProjectId(Long projectId) {
    this.projectId = projectId;
  }

  public LocalDateTime getStartedAt() {
    return startedAt;
  }

  public void setStartedAt(LocalDateTime startedAt) {
    this.startedAt = startedAt;
  }

  public LocalDateTime getEndedAt() {
    return endedAt;
  }

  public void setEndedAt(LocalDateTime endedAt) {
    this.endedAt = endedAt;
  }

  public String getDescription() {
    return description;
  }

  public void setDescription(String description) {
    this.description = description;
  }

  public boolean isBillable() {
    return billable;
  }

  public void setBillable(boolean billable) {
    this.billable = billable;
  }
}
```

1. `@DateTimeFormat(pattern = "yyyy-MM-dd'T'HH:mm")` tells Spring how to convert the text from a
   `datetime-local` input (`2026-09-30T09:00`) into a `LocalDateTime` — and back again when `th:field`
   writes the value into the input after a failed submit.
2. `@AssertTrue` on `isEndAfterStart()`: Jakarta Validation treats the method as a property called
   `endAfterStart` (the `is` prefix is removed, like a boolean getter). If it returns `false`, the error is
   stored under the field name `endAfterStart`. That is why the template shows
   `th:errors="*{endAfterStart}"` under the End input.
3. Both methods return `true` when a date is missing. A missing date is already reported by `@NotNull`;
   we do not want a second, confusing message.
4. `Duration.between(...).compareTo(MAX_LENGTH) <= 0` — exactly 12 hours is allowed, 12 h 1 min is not.
5. In `store()`, the project comes from the database, not from the form. `filter(p -> p.getArchivedAt() == null)`

6. `th:field` on a **checkbox** writes the checkbox and a hidden field `_billable`. When the box is
   unchecked, the browser sends only `_billable`, and Spring sets `billable` to `false`. (In Laravel you
   write that hidden field yourself.)
7. `projects.findByArchivedAtIsNullOrderByNameAsc()` has the entity graph for `client`, so
   `p.client.name` in the option text works with open-in-view off. Try removing the `@EntityGraph`: the
   form page throws `LazyInitializationException`.
8. On errors we add `projects` to the model again; the form object and its errors are already there.

## Troubleshooting

| What you see | Cause | Fix |
|---|---|---|
| `LazyInitializationException: could not initialize proxy [...Project#3] - no Session` | A template or controller touches a lazy relation that the query did not load | Add it to the `@EntityGraph` / `join fetch` of that query. Do **not** switch to EAGER or open-in-view |
| `HHH90003004: firstResult/maxResults specified with collection fetch; applying in memory` | Entity graph with a collection (`tags`) on a query with a limit or `Pageable` | Two queries: ids with limit, then entities by ids (step 7) |
| `Schema-validation: missing table [tag_time_entry]` | Migration not run, or wrong table name in `@JoinTable` | Check the Flyway log and the names |
| `Schema-validation: wrong column type encountered in column [billable]` | Column type in SQL differs from the Java type | `BOOLEAN` ↔ `boolean`, `TIMESTAMP` ↔ `LocalDateTime`, `BIGINT` ↔ `Long` |
| `Validate failed: Migrations have failed validation ... checksum mismatch` | You edited a migration that had already run | Undo the edit and write a new `V5__...` migration instead |
| `Detected resolved migration not applied to database: 3` / versions out of order | Two migrations with the same number, or a lower number than one already applied | Use the next free number |
| Seeder logs "No active projects yet" on every first start | The project seeder runs after the time entry seeder | Give the project seeder `@Order(1)` |
| `Failed to convert property value of type 'java.lang.String' to required type 'java.time.LocalDateTime'` under a field | Input not in `yyyy-MM-ddTHH:mm` format, or `@DateTimeFormat` missing | Add `@DateTimeFormat(pattern = ...)`; for a nicer text add `typeMismatch.java.time.LocalDateTime=Enter a date and time.` to `src/main/resources/messages.properties` |
| The 12-hour error never appears under the field | `th:errors` points at `endedAt` instead of the `@AssertTrue` property | Use `*{atMostTwelveHours}` / `*{endAfterStart}` |
| Same tag shows twice on one entry | `Tag` without `equals`/`hashCode` on the name | Step 2 |
| `DataIntegrityViolationException ... time_entries_project_id_foreign` when deleting a project | Restrict FK: the project has time entries | Archive the project (lesson 05 intermediate) or check for entries first |

```java
/** One row of the weekly report. */
public interface ProjectMinutes {

  Long getProjectId();

  String getProjectName();

  String getClientName();
```

```java
// src/main/java/ee/ta25/billable/report/ReportRepository.java
package ee.ta25.billable.report;

import ee.ta25.billable.timeentry.TimeEntry;
import java.time.LocalDateTime;
import java.util.List;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.Repository;
import org.springframework.data.repository.query.Param;

public interface ReportRepository extends Repository<TimeEntry, Long> {

  @Query(
      value =
          """
          SELECT p.id   AS "projectId",
                 p.name AS "projectName",
                 c.name AS "clientName",
                 CAST(SUM(EXTRACT(EPOCH FROM (e.ended_at - e.started_at))) / 60 AS BIGINT) AS "minutes"
          FROM time_entries e
          JOIN projects p ON p.id = e.project_id
          JOIN clients c ON c.id = p.client_id
          WHERE e.started_at >= :from AND e.started_at < :to
          GROUP BY p.id, p.name, c.name
          ORDER BY c.name, p.name
          """,
      nativeQuery = true)
  List<ProjectMinutes> minutesPerProject(
      @Param("from") LocalDateTime from, @Param("to") LocalDateTime to);
}
```

```java
// src/main/java/ee/ta25/billable/report/ReportController.java
package ee.ta25.billable.report;

import java.time.DayOfWeek;
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;
import java.time.temporal.IsoFields;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.server.ResponseStatusException;

@Controller
public class ReportController {

  private final ReportRepository reports;

  public ReportController(ReportRepository reports) {
    this.reports = reports;
  }

  @GetMapping("/reports/weekly")
  public String weekly(@RequestParam(required = false) String week, Model model) {
    var monday = week == null ? LocalDate.now().with(DayOfWeek.MONDAY) : parseIsoWeek(week);
    var rows = reports.minutesPerProject(monday.atStartOfDay(), monday.plusWeeks(1).atStartOfDay());

    model.addAttribute("week", isoWeek(monday));
    model.addAttribute("monday", monday);
    model.addAttribute("sunday", monday.plusDays(6));
    model.addAttribute("rows", rows);
    model.addAttribute("totalMinutes", rows.stream().mapToLong(ProjectMinutes::getMinutes).sum());
    model.addAttribute("previousWeek", isoWeek(monday.minusWeeks(1)));
    model.addAttribute("nextWeek", isoWeek(monday.plusWeeks(1)));
    return "reports/weekly";
  }

  /** "2026-W40" → Monday of that ISO week. */
  static LocalDate parseIsoWeek(String week) {
    try {
      // ISO week date: "2026-W40-1" is the Monday (day 1) of week 40.
      return LocalDate.parse(week + "-1", DateTimeFormatter.ISO_WEEK_DATE);
    } catch (DateTimeParseException e) {
      throw new ResponseStatusException(
          HttpStatus.BAD_REQUEST, "Invalid week. Use the format 2026-W40.");
    }
  }

  /** Monday 28.09.2026 → "2026-W40". */
  static String isoWeek(LocalDate date) {
    return "%d-W%02d"
        .formatted(
```

- `Repository<TimeEntry, Long>` is the smallest Spring Data interface: no `save`/`delete`, only the
  methods we declare. A read-only report does not need more.
- The aliases are in **double quotes** (`"projectId"`). PostgreSQL turns unquoted names into lower case
  (`projectid`), and the projection getter `getProjectId()` would not find the column.
- `EXTRACT(EPOCH FROM interval)` gives seconds; `/ 60` minutes; `CAST(... AS BIGINT)` returns a `Long`.
- `DateTimeFormatter.ISO_WEEK_DATE` reads the ISO week format, e.g. `2026-W40-1` (year, week, day of
  week). We add `-1` to get the Monday. The formatter is strict: `2026-W60`, `2025-W53` (2025 has only 52
  weeks) and `2026-W4` all throw `DateTimeParseException`.
- `IsoFields.WEEK_BASED_YEAR` (not the calendar year) is important around New Year: 29.12.2025 is in
  `2026-W01`.
- `ResponseStatusException(BAD_REQUEST, ...)` gives a 400 page instead of a 500. The whitelabel page shows
  the message only with `server.error.include-message=always`.
- Summing the few result rows in Java for the total is fine; the heavy work was done in SQL.

<summary><strong>Advanced — prove the query count is constant (Hibernate statistics)</strong></summary>

With open-in-view off, every repository call has its own session, so the per-session `Session Metrics`
log is not a per-**request** number. Hibernate's global `Statistics` object counts all statements since
startup. Reading it before and after a request gives the number for that request.

```java
// src/main/java/ee/ta25/billable/common/QueryCountInterceptor.java
package ee.ta25.billable.common;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.hibernate.stat.Statistics;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.servlet.HandlerInterceptor;

/**
 * Development helper: logs how many SQL statements each request needed and warns above a threshold.
 * Uses global counters, so the numbers are exact only when one request runs at a time.
 */
public class QueryCountInterceptor implements HandlerInterceptor {

  private static final Logger log = LoggerFactory.getLogger(QueryCountInterceptor.class);
  private static final String START = QueryCountInterceptor.class.getName() + ".start";
  private static final long WARN_THRESHOLD = 10;

  private final Statistics statistics;

  public QueryCountInterceptor(Statistics statistics) {
    this.statistics = statistics;
  }

  @Override
  public boolean preHandle(
      HttpServletRequest request, HttpServletResponse response, Object handler) {
    request.setAttribute(START, statistics.getPrepareStatementCount());
    return true;
  }

  @Override
  public void afterCompletion(
      HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) {
    if (!(request.getAttribute(START) instanceof Long start)) {
      return;
    }
    long count = statistics.getPrepareStatementCount() - start;
    var line = "%s %s: %d SQL statements".formatted(request.getMethod(), request.getRequestURI(), count);
    if (count > WARN_THRESHOLD) {
      log.warn("{} — more than {}, possible N+1 problem", line, WARN_THRESHOLD);
    } else {
      log.info(line);
    }
  }
}
```

```java
// src/main/java/ee/ta25/billable/common/QueryCountConfig.java
package ee.ta25.billable.common;

import jakarta.persistence.EntityManagerFactory;
import org.hibernate.SessionFactory;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

/** Active only when Hibernate statistics are switched on (development). */
@Configuration
@ConditionalOnProperty(
    name = "spring.jpa.properties.hibernate.generate_statistics",
    havingValue = "true")
public class QueryCountConfig implements WebMvcConfigurer {

  private final EntityManagerFactory entityManagerFactory;

  public QueryCountConfig(EntityManagerFactory entityManagerFactory) {
    this.entityManagerFactory = entityManagerFactory;
  }

  @Override
  public void addInterceptors(InterceptorRegistry registry) {
    var statistics = entityManagerFactory.unwrap(SessionFactory.class).getStatistics();
    registry.addInterceptor(new QueryCountInterceptor(statistics));
  }
}
```
